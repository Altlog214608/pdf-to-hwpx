# v0.5 — 새 구조로 다시 작성한 첫 Claude 버전

## 1. 왜 다시 작성했나

v0.4.9.5.x는 3만 줄짜리 파일 하나에 버전마다 후처리(finalizer)를 덧붙이는 구조였습니다.
분석 결과(`history/ANALYSIS_v0_4_9_5_23_1-1.md`, `history/ANALYSIS_v0_4_9_5_24_2-x.md`) 다음 문제가 확인됐습니다.

| 문제 | v0.4.9.5.24 | v0.5 |
|---|---|---|
| 박스 하나 실패 → 문서 전체 박스 테두리 사라짐 (2-5) | 단계별 트랜잭션이 연쇄 거부 | 후처리·롤백 없음. HWPX를 IR에서 한 번에 생성 |
| 2단 산문이 PDF 줄마다 문단으로 쪼개짐 (2-2/2-3/2-5) | 글자 수 기준(≤40자) 시 판정 | 줄 오른쪽 끝 위치(기하)로 산문/시 판정 |
| `않은것을`, `(나)의화자`, `(B)이` 띄어쓰기 | 공백 없는 텍스트 레이어 + 조사 붙이기 정규식 | 글자 간격 공백 복원 + 줄 끝 공백 보존, 재띄어쓰기 없음 |
| 시 연 구분 사라짐 | 줄 간격 정보 버림 | 행간 1.7배 이상 → 빈 문단 |
| <보기> 안 ①② 사라짐, 그림만 있는 <보기 2> 누락 | 원문자는 선택지에서만, 그림 박스 미지원 | 원문자 아이콘을 문서 전체에서 판별, 박스 안 그림 지원 |
| 박스 안 그림이 선택지 뒤로 밀림 (2-5 Q7·Q19) | 그림 소유를 지문 단위로만 판단 | 그림 좌표가 박스 안이면 그 박스에 배치 |
| 도식 박스 글자 순서 뒤섞임 (2-5 Q17) | 텍스트로 평탄화 | 박스 안 도형이 4개 이상이면 영역을 그림으로 보존 |
| `- …` 조건 항목이 한 줄로 합쳐짐 | 항목 기호 목록에 `-` 없음 | 항목 기호(`-`,`•`,`ㄱ.`,`A.`,`이름:` 등) 공통 처리 |
| 안내문 원문 대신 고정 문자열 | `※ 다음 글을 읽고 물음에…` 상수 | 원문 그대로 |
| Windows + 한글 COM 필수 | 기본 문서를 COM으로 생성 | 순수 Python(XML) 생성 → Linux/AWS 가능 |
| header.xml 속성 손상 | v5.22 정규식 패치가 `type="PERCENTÌ5"`를 써 넣음 | 템플릿에서 수정, validator가 손상 검사 |
| 실행 시간 / 결과 JSON | 수 분(2-5는 2분 이상) / 10~22MB | 1-1 기준 0.7초 / 약 70KB |
| 코드 크기 | 30,606줄 단일 파일 | 약 2,100줄, 단계별 모듈 |

## 2. 구조

```
v0_5_pdf_to_hwpx.py          실행 파일(한 줄 PowerShell 명령용)
pdf2hwpx/
  extract.py   PDF -> 페이지 모델: 글자 좌표로 줄 재구성, 숨은 글자/머리글/배너 제거, 2단 분리,
               박스(줄 단위 테두리 선분을 이어 붙여 사각형 복원), 밑줄, 원문자 아이콘, 그림, 읽기 순서,
               단/페이지를 넘는 박스 합치기
  ir.py        페이지 모델 -> IR: 지문/문제/보조박스/선택지/정답. 문단 나눔(산문·시·목록·연 구분),
               원문자 아이콘 숫자 판별(선택지 순서 투표 + 픽셀 비교), 문제 번호(기대 번호+큰 글씨+박스 밖)
  hwpx_writer.py IR -> HWPX. 한글에서 검증된 v5.23 결과물의 header.xml을 템플릿으로 사용
               (지문 박스 25, <보기> 51/58/57, 빈 문단 62, 선택지 41/42 …), 변형만 새 id로 복제
  validate.py  패키지/XML/스타일 참조 무결성, 원문 대비 텍스트 커버리지, 박스 수, 박스 뒤 빈 문단,
               문제 순서, 선택지 수, 그림 수 -> PASS/WARN/FAIL + root_causes(근본 원인 한 줄씩)
  convert.py   PDF 한 개 변환(향후 웹 서버도 이 함수를 그대로 호출)
  ir_json.py   IR -> JSON(회귀 비교용)
tests/
  synth_pdf.py        2-x 특징(단 넘김 박스, 박스 안 그림, 도식, 그림만 있는 보기, 글자 단위 줄나눔)을 흉내 낸 합성 PDF
  test_synthetic.py   합성 PDF 전체 파이프라인 테스트
  test_real_samples.py 실제 PDF 폴더 회귀 테스트(PDF2HWPX_SAMPLES)
```

## 3. 결과 JSON 읽는 법

- `validation.status`: PASS / WARN / FAIL
- `validation.root_causes`: FAIL 원인(앞쪽이 근본 원인)
- `validation.checks.text_coverage`: 원문 글자 n-gram이 HWPX에 들어간 비율(1.0 = 누락 없음)
- `validation.checks.missing_source_lines`: 누락 의심 원문 줄
- `document`: 문제·지문·보기·선택지·정답이 원문 순서대로 들어간 IR. 다른 버전과 비교할 때 이 부분을 diff
